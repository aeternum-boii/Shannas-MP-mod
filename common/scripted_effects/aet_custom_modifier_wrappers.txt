## Provides wrapper functions and documentation about custom modifiers to allow for their effects to refresh on daily pulse with little to no performance cost (one bne per modifier). 

# TLDR: We thought modifiers are float32 and thus came from a very different angle. In the end they are int32 and we just use each bit as a flag with bit 30 and 31 reserved for calculations. 
# There also were plans to fit in more than 30 values, but we found proof (it might even be below) that that is impossible :(  (besides giving up bit 30 and making calcs much more complicated)

# Producer signalling:
# Each producer is assigned one bit, represented by a power of two:
#     producer 0 = 1, producer 1 = 2, producer 2 = 4, ... producer 30 = 2^30.
# To add a producer, assign it the next unused power of two and use that
# value for both its addition and its later retraction. Producer 31 is the
# maximum supported producer: bit 31 is the sign bit of int32_t and must not
# be used. Thus at most 31 producers (indices 0-30) are supported per signaling modifier.
#
# Each producer adds its unique power of two when it fires and subtracts the
# same value when it retracts. A producer cannot fire again until it has
# retracted. After the consumer resets x, positive contributions therefore
# come only from producers that fired after the reset, while negative
# contributions come only from producers whose earlier firing occurred before
# the reset.
#
# Powers of two have unique subset sums. Hence two disjoint non-empty sets of
# producers can never have equal total contributions. A non-empty set of new
# contributions therefore cannot be completely cancelled by delayed
# retractions, so x cannot become zero while an unobserved firing remains.
#
# Consequently, testing x != 0 is sufficient to detect that at least one
# producer fired. False positives are harmless; false negatives are
# impossible under the above invariant. x != 0 is equivalent to x >= 0.001 OR NOT (x >= 0)

## When adding a producer:
#   1. Assign the next unused bit (1 << n), where n <= 30.
#   2. Add that value when the producer fires.
#   3. Subtract exactly the same value when it retracts. (this is enforced by eu4 engine) 
#   4. Never allow the producer to fire again before its retraction.
#
# Do not use bits 31 and 30, they are reserved 
# KEEP IN MIND THAT MODIFIERS IN EU4 ARE INT32 / 1000! this means if you use producer with index 0 it has the value of 2^0 = 1. This results in a modifier of 0.001!!!
# Debug modifiers make use of bit 29, so be aware if you use aet_debug mode.

## Functions contained in this class: 
#  consumer_tick_<modifier_name> - tick for applying the modifier 
#  force_reload_<modifier_name> - executes the reload without checking if it is necessary as in consumer_tick_<modifier_name> (this allows use of the modifier without the producer described above)
#  <modifier_name>_sem_reset - helper for consumer_tick_<modifier_name>
#
# The doc of each consumer_tick function contains the next free producer index 
# If possible use force reload instead of a producer, it is much cheaper 

# GE  Modifiers - from /events/GE_scripts.txt

# nsp - GE_script_events

# 2 - rural_goods_produced_modifier
# 4 - urban_goods_produced_modifier
# 5 - mining_goods_produced_modifier

# signal modifier: vassal_tax_modifier_sem 
# current used power of 2: none (next free is 2^0 = 1) 

# This is intended to be ran on daily tick or at the latest at monthly tick
consumer_tick_vassal_tax_modifier = { 
		if { 
			limit {
				aet_is_debug = yes 
			} 
			# This should be a proper loc key but I am lazy 
			#log = ate_advisor_loyal_friend_adm
		}
	if = {
		limit = {
			OR = {
				has_global_modifier_value = {
					which = vassal_tax_modifier_sem
					value = 0.001 
				}
				NOT = {
					has_global_modifier_value = {
						which = vassal_tax_modifier_sem
						value = 0
					}
				}
			}
		}
		if { 
			limit {
				aet_is_debug = yes 
			} 
			# This should be a proper loc key but I am lazy 
			#log = ate_advisor_loyal_friend_adm_desc 
		}
		
		force_reload_vassal_tax_modifier = yes 
		vassal_tax_modifier_sem_reset = yes 
	}
}
